# ANALISE · Збереження локальної тестової перевірки в Cloudflare D1

## Що зберігається

Після локального парсингу DOCX/XLSX та перевірки за фіксованим синтетичним довідником `demo_quality_labels` оператор відкриває «Ручна перевірка тестових значень», підтверджує або пропускає значення, вибирає стандартизовану причину й натискає **«Зберегти тестові результати в D1»**.

До D1 надсилається лише обмежена структура:

- формат: `docx` або `xlsx`;
- ID рядків і узагальнені назви `Таблиця N` / `Аркуш N`;
- тестові назви виключно з allowlist: `Альфа-демо`, `Бета-демо`, їхні синтетичні друкарські помилки, `Невідоме`, порожнє значення;
- статуси відповідності і дозволені opaque ID двох тестових елементів довідника;
- історія дій `map/ignore/undo`, стандартизовані причини, час і стан до/після;
- номер ревізії та виконавець — за чинною Cloudflare Access-авторизацією.

**Не надсилаються:** оригінальні байти DOCX/XLSX, назва файла, інші колонки/клітинки, геокоординати, довільні назви, оперативні записи, необмежені коментарі.

## Таблиця та безпека

Використовується вже наявна `report_versions` з початкової міграції `0001`. Кожне змінене збереження — **новий** рядок, `status='confirmed'`, `report_name=ANALISE-DEMO-LOCAL-V1:<SHA-256 від стабільної частини тестового набору>`. Однакове повторне збереження не створює дубль; конфлікт версій повертає `409`.

Не потрібні нові SQL-міграції чи команда `wrangler d1 migrations apply`. Існуючі 76 демонстраційних Word-записів та аудит `0019` не змінюються.

Код `api/src/demo-local-store-api.js` повторно перевіряє всі поля на сервері (не довіряє клієнтові), обмежує розмір, відхиляє невідомий текст і не дозволяє заднім числом підмінити історію. Запис можливий **лише після явного кліку**, під Cloudflare Access із роллю admin.

## Маршрути

- `POST /api/demo-local-store` — вставити наступну підтверджену ревізію або повернути `reused=true`.
- `GET /api/demo-local-store` — перелік останніх 25 тестових записів (тільки метадані).
- `GET /api/demo-local-store/:hash/latest` — остання збережена ревізія для одного набору.

Клієнтський `generic-preview.js` не виконує `fetch`, звернення винесено в `generic-demo-d1-store.js`, який ніколи не отримує оригінальний файл.

## Приймальна перевірка

1. Після релізу зайти в `/api/generic-preview` через Cloudflare Access.
2. Завантажити **виключно синтетичний** документ із заголовком `Категорія` та `Альфа-демо` / `Невідоме` в потрібній колонці.
3. Підтвердити відповідник тестового запису та вибрати одну зі стандартизованих причин.
4. Натиснути **Зберегти тестові результати в D1**. Дочекатися повідомлення про `cloudflare_d1` і номер ревізії.
5. Натиснути **Показати збережені перевірки**, потім **Переглянути ревізію** — результат має бути реально отриманий із D1.
6. Повторити збереження без змін — очікується `reused=true`; після іншого ручного рішення — нова ревізія.
7. Перевірити, що не створено нових міграцій, старі таблиці не змінені, а POST не містить жодних оригінальних байтів або невідомих значень.

## Обмеження та інші дані

Цей код **не реалізує** серверний імпорт реальних службових Word/Excel даних, роботу з військовими довідниками, повне збереження інших клітинок документа чи перенесення рішень у `dq_occurrences` «Чистилища». Для чутливих даних потрібне окреме погодження інфраструктури, політик доступу та життєвого циклу.

Відкладений ремонт журналу міграцій `0016/0019` лишається окремим завданням, не запускати `migrate-d1.yml` для цього релізу.
