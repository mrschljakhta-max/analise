# ANALISE — локальний конструктор схеми колонок і перевірка даних

Це другий етап універсального парсера на сторінці `/api/generic-preview`.

## Як користуватися
1. Відкрий **Локальний перегляд**, завантаж звичайний цивільний DOCX або XLSX до 8 МБ.
2. Обери таблицю Word або аркуш Excel.
3. У секції **Відповідність колонок** визнач рядок заголовків або «Без заголовків».
4. Для кожного поля вкажи назву цільової колонки, колонку джерела, тип і прапорець «Обов’язкове». Автоматично пропонуються перші 16 колонок; вручну можна задати до 32.
5. Натисни **Перевірити записи**. Побачиш лічильники правильних, помилкових і порожніх рядків, конкретні рядки та поля з поясненням помилок.
6. Якщо потрібен файл, експортуй **лише коректні** рядки у JSON або CSV. Неправильні рядки не потраплять до експорту.
7. Можна зберегти схему у маленький JSON і відкрити її в наступній вкладці/сеансі. Шаблон не містить таблиці, тільки назви полів, типи, позиції колонок і рядок заголовків.

## Підтримувані типи
- **Текст:** обрізає зайві пробіли, до 4096 символів.
- **Ціле число:** перевірка цілих і безпечного діапазону JavaScript.
- **Десяткове число:** кома або крапка як роздільник, без розділення тисяч.
- **Дата:** суворо `РРРР-ММ-ДД` або `ДД.ММ.РРРР`, із перевіркою календаря (у тому числі високосних років).
- **Так/Ні:** `так/ні`, `yes/no`, `true/false`, `1/0`.

Порожні повністю рядки пропускаються. Значення обов'язкових полів мають бути присутні. Некоректні дати (наприклад, 31 лютого) та помилки типу повертають відповідну помилку з номером вихідного рядка. `Word gridSpan` розгортається в позиції колонок без копіювання значень у сусідні поля.

## Дані та безпека
- Під час локального перегляду жоден файл, схема чи зчитані рядки не надсилаються на Worker, D1 або R2; немає XHR/fetch.
- Експорт відбувається лише після натискання на кнопку, без серверних запитів.
- CSV захищає **текстові** рядки, що починаються з `=`, `+`, `-` чи `@`, від небажаного виконання формул.
- Перед кожним експортом треба натиснути перевірку; зміна налаштувань знімає попередній статус перевірки.
- Зміна таблиці обнуляє налаштування зіставлення, щоб уникнути помилкового перенесення колонок між аркушами.
- Є обмеження: до 15 000 рядків/80 колонок у вихідному локальному парсері; до 32 зіставлених полів.
- Локальний перегляд призначено для дозволених документів, **не** для оброблення секретних або актуальних оперативних відомостей.

## Подальший транзакційний D1-імпорт
Цей PR навмисно не містить сервера для прийому довільних JSON/CSV: такий write API без затвердженої схеми і контролю доступу може небезпечно зберігати будь-який вміст. Наступним кроком буде **окремий реєстр дозволених схем** і транзакційний запис лише перевірених дозволених цивільних наборів із журналом, унікальними ключами та контролем версій. Поточні синтетичні записи D1/правила «Чистилища» не зачіпаються.

## Розгортання
Об’єднати PR після CI → **Deploy ANALISE API**. D1 migration не потрібна. Перевірити на нейтральному тестовому XLSX/DOCX (порожні комірки, число з комою, дата, некоректна дата, кілька аркушів). У DevTools → Network не повинно бути POST із вмістом документа.

## Тести
`npm test`, перевірка синтаксису всіх JS, `wrangler deploy --dry-run`. Тести нового ядра `generic-mapping.test.js` перевіряють мапінг Word/Excel, AA-колонку, календарні дати, точні помилки рядків, пропуски, дублікати полів та захист CSV.
