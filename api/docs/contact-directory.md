# ANALISE — приватний довідник контактів

## Вхід і права

- Сторінка: `/api/contacts`
- Стилі: `/api/contacts.css`
- Клієнтський код: `/api/contacts.js`, `/api/contacts-import.js`
- Дані: `GET /api/contacts/data`
- Історія: `GET /api/contacts/history?code=CT-...`
- Створення: `POST /api/contacts/create`
- Редагування: `PATCH /api/contacts/update`
- Перевірка імпорту: `POST /api/contacts/import/prepare`
- Підтвердження імпорту: `POST /api/contacts/import/commit`
- Міграція: `api/migrations/0012_contact_directory.sql`

Усі сторінки, скрипти та API контакту доступні тільки після Cloudflare Access JWT і перевірки ролі адміністратора в D1. Відповіді API мають `private, no-store`. Ні телефони, ні email, ні акаунти DELTA не включаються до загальних підсумків Dashboard — там доступна лише кількість карток.

## Поля картки

- Назва / позивний, альтернативні назви, група
- Телефон, WhatsApp, Signal
- **Акаунт у DELTA** — лише текстовий ідентифікатор; не пароль, не токен
- **Електронна пошта** — необов'язкова, перевіряється формат
- Напрямок, підрозділ, посада / роль та примітки
- Джерело, дата підтвердження, статус перевірки
- Активність, код, версія, дати створення/зміни

Зміни картки журналюються SQL-тригерами з ідентифікатором користувача. Редагування використовує контроль версії. Архівні та суперечливі телефонні записи не перезаписуються імпортером.

## Excel

Підтримуються аркуші `DICT_CONTACT`, `КОНТАКТИ`, `CONTACTS` у файлі `.xlsx`. Для імпорту обов'язкова назва контакту. Інші колонки необов'язкові: «Телефон», «WhatsApp», «Signal», «Акаунт в дельті / DELTA», «Електронна пошта», «Група», «Підрозділ», «Посада / роль», «Напрямок», «Примітки», «Альтернативні назви».

Якщо в Excel немає стовпця «Група», адміністратор мусить вибрати групу перед перевіркою. Якщо групи різні, у попередньому перегляді можна змінити групу кожного рядка. Значення `543` не вважається підрозділом. Імпортовані картки завжди мають статус «Не перевірено» до окремого підтвердження.

Майстер: локальна перевірка → порівняння з D1 → явне підтвердження. Виявляються повтори назв у групі, розбіжності в телефоні/email/DELTA для наявних записів та повторне використання номера серед різних контактів. Наявні картки не переписуються. Після D1.batch виконується повторна перевірка фактичного збереження, незалежно від значення лічильника тригерних змін.

**Реальні контакти не закладені у репозиторій та не переносяться автоматично.** Спочатку перевір міграцію та інтерфейс на тестових записах, а вже потім завантажуй персональні дані в захищеному середовищі.

Модуль не будує автоматичних маршрутів зв'язку між конкретними військовими адресатами і не призначений для оперативної координації.

## Запуск

1. GitHub Actions → `ANALISE D1 schema migration` → `Run workflow` (main).
2. GitHub Actions → `Deploy ANALISE API` → `Run workflow` (main).
3. Відкрий `/api/contacts` під адміністраторським обліковим записом, перевір створення та редагування синтетичної картки, журнал.
4. Перевір Excel локально, подивись попередній перегляд та порівняння. Не підтверджуй імпорт, доки дані не перевірено.

Контактні дані потребують обмеженого доступу й регулярного перегляду актуальності. Резервне копіювання та відповідність локальним правилам обробки персональних даних потрібно налаштувати окремо.
