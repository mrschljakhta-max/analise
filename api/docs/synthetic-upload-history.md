# ANALISE · Історія тестових імпортів і зрозумілий аудит

## Межі цього етапу
Це поліпшення лише синтетичного модуля `/api/synthetic-upload` та
візуального журналу `/api/purgatory`. Воно **не** додає підтримку
оперативних військових звітів і **не** змінює існуючі довідники або правила.

## Після міграції 0015
- `demo_import_sessions`: сеанс одного перетягування (кількох файлів або ZIP).
- `demo_import_documents`: знеособлені результати розпізнавання окремих
  документів, стан **на момент імпорту** і короткий перелік синтетичних
  рядків, придатний для детального перегляду.
- Оригінали файлів не зберігаються у D1 або R2.
- Історія починає накопичуватися після розгортання 0015; попередні
  завантаження не відновлюються заднім числом.
- Повторний запит з тим самим ID сеансу та ідентичним вмістом не створює
  дубліката документа. Нове перетягування створює новий сеанс історії.
- Фільтр за календарною датою в інтерфейсі використовує дату D1 (UTC).
- Перегляд історичного запису **не** повторює імпорт і не змінює
  підтверджені правила; журнал показує попередній стан як зафіксований.

## API
- `GET /api/synthetic-upload/history?date=YYYY-MM-DD&offset=0` — 30 сеансів
  і прапорець наступної сторінки.
- `GET /api/synthetic-upload/history/{uuid}` — документи та синтетичні
  дані сеансу для розгортання в таблиці.
- `POST /api/synthetic-upload/ingest?name=...&session={uuid}` — попередній
  тестовий імпортер, доповнений записом сеансу в D1.
- Усі маршрути потребують автентифікації через Cloudflare Access,
  ролі адміністратора й чинної D1.

## Журнал Чистилища
Колишні `before_json` і `after_json` **не змінюємо**. На сторінці
показуємо зрозумілий тип події, автора, час, значення, статус до/після,
підтверджений відповідник та розгортання джерела.

## Перевірки та розгортання
1. Об'єднати PR після проходження GitHub CI.
2. Запустити **ANALISE D1 schema migration**, дочекатися зеленого стану.
3. Запустити **Deploy ANALISE API**.
4. Відкрити Центр завантаження, повторно перетягнути синтетичний ZIP.
5. Побачити нову картку в «Історії завантажень», відкрити старий
   результат, використати фільтр дати.
6. Перейти до «Чистилища» → «Історія рішень» та перевірити новий
   читабельний вигляд на наявних тестових записах.
7. Переконатися, що лічильники й затверджені правила залишилися незмінними.

**Примітка:** обробка все ще синхронна; фонова черга і зберігання
оригіналів реальних документів не є частиною цього етапу.
