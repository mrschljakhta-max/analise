# ANALISE — автоматичний структурний парсинг DOCX/XLSX (локально)

## Де відкривати

Після рев'ю, злиття PR і підтвердженого deploy: `/api/generic-preview` (захищено Cloudflare Access, роль admin).
Завантажити цивільний або синтетичний DOCX чи XLSX до 8 МБ. Новий блок «Автоматичний структурний парсинг» з'являється без налаштування відповідності колонок.

## Функціонал

- **DOCX:** знаходить структурно сумісну чотириколонкову таблицю, у якій уже застосовано наявний локальний поділ першої та третьої колонок. Групові рядки, повторні заголовки й пусті рядки не стають записами. Відповідно до правила поділу отримує шість нейтральних полів; початкові значення чотирьох клітинок зберігає окремо, без нормалізації пробілів.
- **XLSX:** визначає таблицю за фізичними рядками/комірками, читає значення із збереженням адрес `A1`, `AA2` тощо, кешованих значень формул, сирих значень і типів. Перший заповнений рядок із >=3 значеннями може бути визначений заголовком за наявності >=2 текстових значень та наступних рядків.
- **Помилки:** нерозпізнані структури не видаються за успішний імпорт; некоректні рядки залишаються у локальному результаті з `valid: false` та описом проблеми.
- **Результат:** кількість таблиць, записів і рядків на перевірку, короткий перегляд, кнопка завантаження JSON із полями `raw_cells`, `source_row`, `values`, `issues`.
- Старий ручний конструктор колонок зберігається нижче для інших цивільних форматів.

## Важливі обмеження

1. Це **локальний** браузерний етап, не серверний імпорт. Не записує оригінали, JSON або нормалізовані значення в Cloudflare D1/R2.
2. Немає звірки з довідниками D1 чи застосування правил «Чистилища».
3. За раз завантажується один DOCX або XLSX; ZIP-пакети та папки поки не реалізовані.
4. Excel автоматично розбирається **структурно**, але не зіставляє поля з конкретною службовою моделлю; зберігає адреси та порядок колонок.
5. Не виконує геоаналітику, прогнозування маршрутів, підготовку оперативних рішень.
6. Не використовувати для несанкціонованих документів із обмеженим доступом. Факт локального парсингу не робить браузер автоматично дозволеним середовищем для секретних даних.

## Приймальна перевірка без реальних даних

1. Синтетичний DOCX: 79 рядків, 1 заголовок, 2 об'єднані групові рядки, 76 рядків даних. Очікується 76 записів.
2. DOCX з помилковими датами або числовим полем: рядки не зникають, потрапляють до `needs_review`.
3. DOCX із невідповідною структурою: показати причину, без автоматичного зіставлення.
4. XLSX із колонками A–AA: перевірити правильні адреси, вихідні номери рядків, значення.
5. Excel із формулою без кешованого значення: повідомлення про проблему.
6. DevTools → Network: вибір файлу не повинен викликати POST документа на Worker.
7. JSON містить усі оброблені рядки та причини помилок; на D1/R2 змін немає.
