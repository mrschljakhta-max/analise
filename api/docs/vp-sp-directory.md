# ANALISE — довідник ВП/СП (перша версія)

Цей модуль створено як **обліковий каталог назв об'єктів**. Він не призначений для зберігання оперативних координат, розгортань чи організаційної приналежності конкретних позицій.

## Розділи

- Каталог: `/api/vp-directory`
- API списку: `GET /api/vp-directory/data`
- API історії: `GET /api/vp-directory/history?code=...`
- Створення / редагування: `POST /api/vp-directory/create`, `PATCH /api/vp-directory/update`
- Попередня перевірка імпорту: `POST /api/vp-import/prepare`
- Підтвердження імпорту: `POST /api/vp-import/commit`
- Схема D1: `api/migrations/0011_vp_sp_name_directory.sql`

Усі маршрути потребують Cloudflare Access і ролі `admin`.

## Структура Excel

Підтримуються `.xlsx` з аркушем `ДОВІДНИК_ВП` і колонкою `Назва ВП`, а також за потреби аркуш `ДОВІДНИК_СП` та колонка `Назва СП`.

Додаткові колонки, зокрема `Підрозділ об'єкта` й `Координати MGRS`, можуть бути присутні у вихідному Excel, але **не надсилаються в API й не зберігаються у D1**. У браузері формується лише агрегований підрахунок заповненості цих колонок, без їхніх значень.

До серверного імпортера допускається тільки масив об'єктів `{source_row, kind, name}`. Будь-які додаткові поля відхиляються.

## Нормалізація

1. Початкове `ВП ` / `ВП.` / `ВП-` видаляється.
2. `Матє` нормалізується до `Мате`.
3. Повторні назви з одним типом об'єкта об'єднуються.
4. Порожні назви та узагальнення `Об'єкт прикриття`, `інше` не імпортуються.
5. ВП і СП ведуться окремими типами. Для СП дозволено нуль записів.
6. Імпорт — лише нові записи; потрібні попередня перевірка та явне підтвердження. D1 фіксує створення та редагування в журналі.

## Майбутня ієрархія

За вимогами проєкту рівні підпорядкованості в майбутньому можуть включати дивізіон → рота/батарея → взвод. Наявність такої ієрархії **не означає, що в поточній версії можна приєднати її до точних позицій**. Ці зв'язки не збираються цим модулем, і жодних значень не вигадують.

## Розгортання

1. GitHub Actions: `ANALISE D1 schema migration` — запускається один раз, застосовує 0011.
2. GitHub Actions: `Deploy ANALISE API` — перевіряє синтаксис, запускає тести і розгортає Worker.
3. У вебінтерфейсі відкрити каталог ВП/СП, вибрати Excel, перевірити попередній перегляд, порівняти з D1, підтвердити імпорт.

Не імпортуйте неочищені дані вручну через SQL. Модуль навмисно не має колонок географічного розташування й підрозділів.
