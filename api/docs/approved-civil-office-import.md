# ANALISE · Підтверджений цивільний імпорт у Cloudflare D1

## Реалізовано
Це перший **дійсний транзакційний write path** після універсального браузерного парсера DOCX/XLSX. На цей момент серверний імпорт дозволено **лише** для схеми `office_inventory_v1` — обліку канцелярських товарів.

Універсальне збереження довільного змісту Word/Excel, довільних колонок, персональних даних, координат і оперативних військових записів **не підтримується**. Інші набори залишаються у локальному попередньому перегляді без запису у D1.

## Безпечна схема `office_inventory_v1`
Дозволені чотири поля:
- `item` — назва з точного списку: **Папір А4**, **Ручка**, **Олівець**, **Зошит**, **Папка**, **Скріпки**, **Стікери**, **Конверт**, **Клей**, **Маркер**.
- `quantity` — ціле число 0–100000.
- `stock_date` — коректна дата ISO від 2020-01-01 до 2035-12-31.
- `unit_price` — необов'язкова числова ціна в грн, від 0 до 100000, максимум 2 знаки після коми.

Всі інші поля, наприклад `note`, `filename`, `mgrs`, `lat`, `lon`, `contacts`, `email` або будь-яке довільне текстове значення відхиляються. На сервер потрапляє лише дозволений структурований JSON (до 100 рядків і 64 КБ), **оригінали DOCX/XLSX та їх назви не надсилаються і не зберігаються**.

Для кожного `(товар, stock_date)` у базі є одна чинна кількість:
- повтор точно однакових даних не створює нового рядка;
- повтор ідентичного набору не створює новий сеанс імпорту;
- інше значення кількості/ціни за ту саму дату спричиняє **409 Conflict** і повністю відхиляється;
- SQL-тригер запобігає перезапису при паралельних запитах; усі записи одного імпорту виконуються **атомарно** через `DB.batch`.

Система **не** робить тихої заміни або затвердження нової версії існуючого запису. Це окрема майбутня функція.

## Нові таблиці D1 — міграція 0017
- `civil_office_imports`: ID сеансу, hash нормалізованих даних, автор, кількість рядків і час.
- `civil_office_items`: лише дозволені категоріальні значення, кількість, дата обліку, ціна в копійках, походження рядка.
- `civil_office_audit`: автоматичний append-only аудит імпорту й нових записів.

Міграція **лише створює** нові таблиці/індекси/тригери. Існуючі довідники, «Чистилище», попередні сеанси, версії та записи не змінюються.

## Робота на сайті
1. Відкрити `/api/generic-preview`, вибрати звичайний цивільний DOCX/XLSX.
2. У локальній схемі натиснути **«Підставити схему канцелярії»**; звірити `item`, `quantity`, `stock_date`, `unit_price` з відповідними колонками документа.
3. Натиснути **«Перевірити записи»**. Для D1 не допускаються рядки з помилками.
4. Натиснути **«Перевірити для D1»** — тільки тепер дозволені структуровані записи (але не сам файл) передаються Worker для серверної перевірки.
5. Побачити кількість нових і вже наявних записів або конфлікт.
6. Відмітити підтвердження і натиснути **«Зберегти в D1»**. Система запитає фінальне підтвердження.
7. Відкрити `/api/database-viewer?dataset=office_inventory` (посилання під результатом). Там записи можна шукати, сортувати, переглядати картки й експортувати поточну сторінку. Також доступний окремий набір «Канцелярія · Імпорти».

## API
- `POST /api/approved-import/inspect` — перевірка без запису. Повертає `fingerprint`, `new_rows`, `existing_rows`.
- `POST /api/approved-import/commit` — та сама схема та записи, додатково `confirmed:true` і `expected_hash` з відповіді попередньої перевірки; атомарний запис в D1.
- `GET /api/database-viewer/catalog` і `GET /api/database-viewer/data?dataset=office_inventory` — read-only перегляд з браузера.

Усі маршрути — лише після Cloudflare Access та з активною роллю `admin`. Права перевіряються сервером, а не покладаються на прапорець у браузері.

## Розгортання
1. Дочекатися зеленого GitHub CI й об'єднати PR.
2. Запустити [ANALISE D1 schema migration](https://github.com/mrschljakhta-max/analise/actions/workflows/migrate-d1.yml) (міграція **0017**).
3. Після її успішного завершення — [Deploy ANALISE API](https://github.com/mrschljakhta-max/analise/actions/workflows/deploy-api.yml).
4. Перевірити імпорт вигаданого документа з канцелярськими товарами; повтор імпорту та конфліктну кількість.
5. Переконатися, що 48 тестових виправлених входжень і 2 правила збережені без змін.

## Тести
`api/tests/approved-office-import.test.js`: схеми й відхилення зайвих полів, правильна дата, сума в копійках, транзакційність/ROLLBACK, захист від дублювання, 403/405/409, поява записів у read-only D1 viewer та браузерне явне підтвердження.

## Межі
Це **не** універсальний імпортер довільних службових документів. Для нового цивільного набору потрібна окрема затверджена серверна схема, відповідні перевірки, UI та контроль прав. Гриф документів та організаційну політику доступу визначає власник інформації, не сам сайт.
