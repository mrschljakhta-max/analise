# Якість архівів: агрегований імпорт (ANALISE)

## Призначення
Безпечний стартовий модуль для **кількісного обліку структури архіву**, а не для аналізу роботи військових засобів.
Ніякі файли, назви файлів, позиції, координати, частоти, особи, станції, детальні записи або часові ряди подій не передаються в нові таблиці.

## Архітектура
- Додаткова міграція `0020_quality_inventory.sql` створює **окремі** таблиці та read-only view.
- Існуючі `source_files`, `import_batches`, `operational_report_*`, довідники та `dq_*` не змінюються.
- Усі маршрути захищені чинним Cloudflare Access, роль **admin**.
- `GET /api/quality-inventory` повертає до 50 пакетів та сумарні кількості.
- `POST /api/quality-inventory` приймає лише явно дозволену схему; повтор з тим самим ключем/тілом ідемпотентний.
- `GET /api/quality-inventory/view` — захищена сторінка імпорту та перегляду.

## JSON для імпорту
```json
{
  "batch_key": "archive_example_01",
  "nested_archives": 0,
  "files": [
    {"format": "xlsx", "total": 3, "unique": 2},
    {"format": "docx", "total": 1, "unique": 1}
  ]
}
```

Кількість дублікатів розраховується автоматично: `total - unique`.
Якщо ZIP містить вкладений ZIP із копіями файлів, **рахуємо лише файли верхнього рівня**. Кількість вкладених архівів вказуємо окремо, щоб не подвоїти статистику.
Для захисту від повторного імпорту використовуйте унікальний `batch_key`.
Не розміщуйте JSON конкретних архівів у публічному GitHub.

## Порядок запуску
1. Зробити backup D1 та перевірити доступ до чинної бази.
2. У гілці перевірити `cd api && npm test`.
3. Після перегляду PR застосувати міграцію через існуючий workflow `migrate-d1.yml`.
4. Розгорнути Worker (існуючий `deploy-api.yml`) і перевірити Cloudflare Access.
5. У приватному інтерфейсі відкрити `/api/quality-inventory/view` та імпортувати **лише агрегований JSON**.
6. Переконатися, що повтор не створює дубль і що читання повертає ті самі підсумки.

## Обмеження
Модуль **не** завантажує Word/Excel/PDF, не працює з тактичними подіями та не підтверджує точність детальних даних.
Він заповнює перший шар метаданих, на якому можна побудувати безпечні KPI якості архівів.
