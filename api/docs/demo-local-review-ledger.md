# ANALISE: ручна перевірка та журнал рішень (демо)

Цей етап додає **локальне** підтвердження результатів звірки синтетичних назв, отриманих з чинного довідника `demo_quality_labels` у Cloudflare D1. Жодних нових таблиць, міграцій чи POST документів на сервер немає.

## Сценарій

1. Відкрий захищений `/api/generic-preview`.
2. Завантаж синтетичний DOCX/XLSX із заголовком `Категорія` або `Назва`; перевірка отримує до 39 елементів тестового довідника.
3. Знайдені однозначні збіги залишаються без ручних змін.
4. Значення `missing`, `ambiguous`, `empty` можна вибрати зі списку. Вкажи причину рішення (від 3 до 240 символів) та натисни **Підтвердити відповідник** (лише для непорожнього значення) або **Пропустити**.
5. Скасування останнього рішення не видаляє подію з історії: додається нова подія `undo`.
6. Експортуй JSON із блоками `reference_check` (вихідні результати звірки) та `reference_review` (остаточні рішення, первинні значення, історія й причини).

## Гарантії

- Вихідні значення документа залишаються без змін, у журналі видно стан до/після.
- Відповідник можна обрати лише з реально завантажених тестових записів, нові значення не записуються в довідник.
- Для неоднозначної **колонки** (`ambiguous_mapping`) немає автоматичного вибору: її необхідно розглядати окремо.
- Весь журнал існує лише в пам'яті вкладки до закриття/оновлення сторінки; щоб зберегти його, **обов'язково завантаж JSON**.
- `persisted_in_d1: false` — підтвердження не оновлює `Чистилище` чи D1.
- Права Cloudflare Access і наявні серверні API не змінюються.
- Виключно неоперативні демонстраційні документи. Це не перевірка військових або географічних довідників.

## Приймальні тести

`cd api && npm test`

Перевірити ручну відповідність, пропуск, зміну рішення, відкат, незмінність початкових значень і повноту експортованого JSON. Після окремого code review і погодження деплою можна перевіряти сторінку у браузері.
