# ANALISE — оглядач Cloudflare D1 (read-only)

Маршрут: `/api/database-viewer`, лише автентифікований активний адміністратор через Cloudflare Access.

## Навіщо
Це **реальні дані, які вже лежать у D1**, а не тимчасова таблиця браузерного попереднього перегляду. На сторінці можна обрати дозволений набір, побачити загальну кількість записів, знайти потрібне значення, змінити порядок, відфільтрувати за станом, перейти між сторінками й відкрити деталі окремого запису. Є CSV-експорт **лише поточної сторінки**.

## Дозволені набори

| Набір | Що показує |
|---|---|
| Каталог довідників | Назви, коди, версії й дати оновлення з `directory_types`, без записів інших довідників |
| Тестовий довідник | Вигадані назви з `directory_entries` лише для `demo_quality_labels` |
| Входження «Чистилища» | Лише вигадані входження, створені синтетичним джерелом |
| Правила пам'яті | Вигадані правила `demo_quality_labels` |
| Сеанси завантажень | Показники синтетичних сеансів із `demo_import_sessions` |
| Тестові документи | Метадані та дозволені вигадані рядки з `demo_import_documents` |
| Версії документів | Чинні та архівні синтетичні версії `demo_report_versions` |

**Інші таблиці** (`users`, контакти, координати, оперативні записи, необмежений `records`, файли, загальний аудит, тощо) **навмисно недоступні** в цьому інтерфейсі. Для чинних довідників вже є окремі захищені сторінки. Це не SQL-консоль і не автоматичний експорт усієї бази.

## API й права

- `GET /api/database-viewer/catalog` — перелік семи фіксованих наборів, кількості, можливі фільтри; якщо міграції немає, відповідний набір позначається недоступним.
- `GET /api/database-viewer/data?dataset=demo_documents&offset=0&q=&sort=recent&filter=all` — до 25 рядків із D1, параметризований пошук, обмежена пагінація.
- `GET /api/database-viewer/data?dataset=demo_documents&id=...` — деталі за ID із фіксованого набору й очищений синтетичний знімок.

Запити `POST`, `PATCH`, `DELETE` відхиляються. Клієнт не може передати SQL, назву таблиці, назву колонки, сорт-фрагмент або власний фільтр. Кожен датасет описаний серверним білим списком. Пошукові значення та IDs прив'язуються параметрами. Параметри сторінки й довжина пошуку обмежені. Всі клієнтські значення вставляються в DOM через `textContent` замість `innerHTML`. Обмежений експорт CSV екранованих текстів не виконує формули.

Відповіді мають приватні no-store заголовки; URL, JS, CSS і API захищені існуючою авторизацією. Потрібна активна роль `admin`.

## Як перевірити

1. Об'єднати Pull Request після успішного CI.
2. Запустити **Deploy ANALISE API**. **Міграція D1 не потрібна**.
3. Відкрити `/api/database-viewer` через меню «Розділи» → «База даних».
4. Знайти синтетичні входження «Альфа деммo» і правила, а також історичний сеанс із 2 документами й 97 рядками (якщо такі дані збереглися).
5. Переглянути картку тестового документа: дозволені вигадані рядки без оригінального DOCX/XLSX.
6. Перевірити вибір фільтрів, сортування, пошук «альфа», наступну/попередню сторінку та CSV.
7. Переконатися, що каталог інших довідників показує тільки метадані й надає посилання на наявні спеціалізовані сторінки.

Наявні дані D1/«Чистилища», правила, синтетичні сеанси та їх версії **не змінюються**. Новий оглядач не приймає документів на імпорт і не відкриває доступ до чутливих наборів даних.
