# ANALISE — тестова перевірка локального парсингу за довідником D1

## Реалізовано

Після автоматичного розбору DOCX/XLSX у `/api/generic-preview` браузер окремим **GET** читає лише назви й ID з існуючого **синтетичного** довідника `demo_quality_labels` через `/api/purgatory/candidates?directory_id=demo_quality_labels`.

Вміст завантаженого документа, його клітинки, назва файла та JSON **не передаються** до D1. Порівняння проводиться у браузері, результати додаються до кнопки локального експорту JSON у полі `reference_check`.

- `matched` — нормалізований точний збіг з одним чинним записом;
- `missing` — значення відсутнє в завантаженому повному тестовому списку;
- `ambiguous` / `ambiguous_mapping` — більше одного відповідного запису або неможливо однозначно обрати колонку;
- `empty` — поле не заповнено;
- `unmapped_tables` — система не визначила відповідний стовпець; **жодне поле не вгадується**;
- `unavailable` — не вдалося отримати довідник; **це не означає відсутність значень**.

Обсяг перевірки обмежений тестовими назвами: у сумісному Word це друга вихідна колонка з заголовком «Категорія» або «Назва»; в Excel — єдина колонка з цим очевидним нейтральним заголовком. Якщо заголовків кілька або немає — перевірку поля пропускаємо.

Нормалізація: Unicode NFC, уніфікація типографських апострофів і дефісів, пробілів, регістру. Не виконується автоматичне виправлення помилок і не створюється запис у «Чистилищі».

## Обмеження

Ця перша інтеграція використовує лише дозволений тестовий довідник із двома вигаданими назвами. Вона **не** перевіряє підрозділи, населені пункти, станції, БпЛА, контакти, координати чи переміщення; не записує нічого до D1, не змінює статуси в «Чистилищі» й не запускає бойову аналітику.

Для неоперативних та цивільних наборів наступними кроками можуть бути окремі дозволені профілі звірки, перевірка повноти результатів із пагінацією, тестування конфліктів і ручне підтвердження неоднозначностей.

## Перевірка

1. Відкрити `/api/generic-preview` під Cloudflare Access.
2. Вибрати синтетичний DOCX із другою колонкою «Категорія» або XLSX із заголовком «Назва».
3. Використати `Альфа-демо`, `Бета-демо`, `Невідоме`: очікується 2 збіги та 1 «невідоме» (за умови відповідного вмісту тестового довідника D1).
4. Дочекатися блоку «Перевірка за тестовим довідником D1» та експортувати JSON; перевірити `reference_check`.
5. За збою GET переконатися, що показано `unavailable`, а не «все відсутнє».
6. Перевірити DevTools → Network: **не повинно бути POST із вмістом документа**.

Тести: `cd api && npm test`. Зміни не потребують SQL-міграцій.
