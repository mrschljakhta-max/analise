# Імпорт адміністративного довідника станцій у D1 (v1)

## Маршрут і доступ
- Сторінка: `/api/station-import` (адміністратор через Cloudflare Access).
- Перевірка `.xlsx` і читання трьох аркушів відбувається в браузері.
- `GET /api/station-import/org-units`: лише читання підрозділів `org_units`.
- `POST /api/station-import/prepare`: сувора перевірка облікових полів, відповідностей та дублювань, **без запису**.
- `POST /api/station-import/commit`: створення нових записів лише з незмінним SHA-256 від попереднього перегляду та підтвердженням `IMPORT_NEW_ONLY`.

## Захист наявних довідників
- Використовуються лише `INSERT INTO station_types`, `INSERT INTO station_type_antennas`, `INSERT INTO stations`.
- Немає `UPDATE`, `DELETE`, очищення таблиць або створення нових підрозділів.
- `org_units` і `directory_entries` **ніколи не змінюються** в цих маршрутах.
- Підрозділ з Excel зіставляється за точним внутрішнім ID, `import_key` або `unit_code`. Відсутні відповідності вимагають ручного вибору користувачем.
- Порожня назва й ID підрозділу дозволяють `NULL` лише якщо обидва відсутні у файлі, з явним попередженням.
- Перед записом перевірка повторюється; збіг будь-якого імпортного коду в D1 блокує весь імпорт.
- Вставки об'єднані в одну транзакційну операцію D1 `batch`; часткові успішні записи неприпустимі.

## Сфера даних
- Три групи: моделі, характеристики моделі та облікові записи станцій.
- Сервер приймає тільки поля з білого списку. Excel не передається як файл.
- Географічні координати, населені пункти, MGRS, історія розміщення, режими поточної роботи й оперативні статуси не передаються/не імпортуються.
- Із таблиць D1 зчитуються коди та ідентифікатори для попереднього порівняння; на сторінці імпорту не відображаються дані розміщення.
- Для нових записів застосовуються безпечні значення за замовчуванням D1: `deployment_status='not_deployed'`, `operational_status='inactive'`.
- Це **створення тільки нових** записів; редагування існуючих — окреме майбутнє завдання.

## Перевірка перед використанням
1. `cd api && npm test` — локальні тести валідації, контролю доступу, конфліктів, підтвердження й транзакцій.
2. Запустити Deploy ANALISE API у GitHub Actions; впевнитися, що Worker доступний через Cloudflare Access.
3. Відкрити сторінку імпорту, вибрати Excel, пройти локальну перевірку.
4. Прив'язати коди підрозділів до `org_units` у формі.
5. Виконати «Підготувати імпорт»; переглянути всі зауваження й кількість записів.
6. Лише за усвідомленого підтвердження натиснути запис до D1; потім перевірити нові рядки в довіднику станцій.

**Увага:** жоден виклик GitHub не завантажує дані з Excel у D1. Запис відбудеться лише від підтвердженої дії адміністратора на сторінці після деплою.
