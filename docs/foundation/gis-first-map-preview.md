# ANALISE / OSM MAP STUDIO — перший інтерактивний екран

## Де відкрити

**`https://analise-api.mr-schljakhta.workers.dev/api/gis-preview`** — під існуючим Cloudflare Access `analise-api`, лише активний `admin`. У верхньому меню ANALISE є окреме посилання «Карта».

**Призначення:** показати користувачу реальне картографічне полотно вже в Foundation, не чекаючи всіх інфраструктурних робіт. Це оглядовий прототип, **не GIS Core, не випуск OSM MAP STUDIO v1.0**.

## Що вже можна перевірити

- Панорамування карти мишкою та сенсорним перетягуванням; масштаб колесом, кнопками `+` / `−` і клавішами.
- Реальні **растрові плитки OpenStreetMap** з видимим атрибутуванням; вони завантажуються браузером без стороннього JavaScript. Доступність підкладки залежить від мережі та tile.openstreetmap.org.
- Вкл./викл. підкладку і шар **трьох синтетичних точок** у нейтральному регіоні (Лісабон), вибір точки й інспектор атрибутів.
- Виведення центральних WGS84 координат, масштаб, повернення до демонстраційного району.
- Панелі «Проєкт», «Шари», «Інструменти», «Інспектор», responsive-вигляд.

## Обмеження і безпека

- Жодних запитів до `analise-db`, GIS D1/R2/KV/Queue або RAW-документів.
- Немає геоаналітики, імпорту, збереження, серверних прав і створення реальних проєктів.
- Не використовує службові координати, реальні шари або маршрути.
- Головний GIS SPA на React + MapLibre розташований у `gis/apps/web` та все ще **не опублікований**; цей оперативний перший перегляд використовує незалежний мінімальний JavaScript-рендерер OSM-тайлів без зовнішніх JS CDN. Наступний етап — авторизовані GIS Workers і збірка MapLibre під ізольованими ресурсами.
- Ресурси D1/R2 Dev і Staging залишаються недоторканими. Існуюча Access-політика ANALISE не змінюється.
- Підкладка OSM — стороння мережа: публічному tile-серверу передаються **лише запити демонстраційних плиток карти**; реальних даних немає. Для production слід обрати окремого tile-провайдера / кеш із дотриманням політик.

## Тест

`cd api && npm test`; тести `api/tests/gis-preview.test.js` перевіряють синтаксис, маршрути, CSP, заголовки, елементи UI, відсутність зв'язку з D1 і меню адміністратора.

Очікуваний результат після публікації: відкрити URL після Cloudflare Access і одразу побачити карту. Якщо тайли не підтягуються, залишиться робочий інтерфейс і повідомлення про проблему із завантаженням підкладки.
