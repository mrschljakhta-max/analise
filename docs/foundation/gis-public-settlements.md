# OSM MAP STUDIO · Публічні населені пункти Cloudflare D1

## Scope

Підключено лише **відкритий довідник населених пунктів** до карти; це не загальний механізм виведення будь-яких довідників. Дані беруться з уже наявної таблиці `directory_entries` для **єдиного** коду `directory_id='settlements'`.

Авторизований адміністратор ANALISE відкриває `/api/gis-preview`, розгортає ліву панель та вмикає `Населені пункти (D1)`. За замовчуванням цей шар **увімкнений** і читає D1 автоматично, без натискання на перемикач. Демонстраційні точки автоматично приховуються.

## Безпека і формат

- Новий endpoint `GET /api/gis/settlements?south=...&west=...&north=...&east=...`.
- Cloudflare Access перевіряє токен ще до маршруту, далі обов'язковий активний `admin`.
- Приймає лише коректний bounding box до **14° широти та 24° довготи**. Для огляду більшої області потрібно збільшити карту.
- Повертає до **200** записів за сторінку (`offset=0,200,…,1800`), з максимумом **2 000** на одну видиму область. Список включає лише публічні цивільні поля `id,name,type,community,district,region,lat,lon`. Поля `more`, `next_offset`, `truncated` сигналізують про неповне охоплення й потребу збільшити масштаб.
- Пошук лише в публічному цивільному довіднику. Не повертаємо `data_json` цілком, MGRS, персональні дані чи будь-які військові таблиці.
- **Read-only:** тільки SQL `SELECT`. Жодних міграцій і змін до D1/R2.
- Навігація по карті призводить до запиту після затримки 450 мс, попередній запит скасовується, якщо карта змінилася.
- Маркери позначають умовні географічні центри населених пунктів із D1, а не військові позиції.
- За масштабу менше 7 або надто широкого охоплення шар підказує збільшити карту. Щільні групи населених пунктів відображаються кластерами; натискання на кластер наближає карту.
- Шар жодним чином не додає до карти оперативні БпЛА, ВП/СП чи дані станцій/їхньої геометрії.

## Обмеження

Точність координат залежить від вмісту довідника. Код не гарантує, що у Cloudflare D1 є населені пункти з валідними `lat/lon`; якщо немає, відобразиться **0**. Не робити твердження про завантаження конкретних поселень без фактичного smoke-тесту.

Точні позиції захищених об'єктів, маршрути БпЛА та сектори роботи військової техніки тут не підключаються. Для спільного інтерфейсу можуть використовуватися лише синтетичні навчальні шари або несекретні агреговані статистичні дані.

## Smoke test

1. Відкрити /api/gis-preview під Cloudflare Access з активним admin.
2. Кнопкою керування шарами відкрити ліву панель і поставити прапорець `Населені пункти (D1)`.
3. Пересунути карту та змінити масштаб: індикатор повинен показати кількість записів, точки перемістяться відповідно до підкладки.
4. Натиснути на точку: показується назва та тип із публічного довідника.
5. Вимкнути шар: маркери зникають. Перевірити, що D1-процес імпорту та інші модулі ANALISE не змінені.
6. `cd api && npm test`, Worker bundle, після мерджу Cloudflare Deploy.

## 18.10.2026 · Робоча карта цивільних точок з D1

- Заходячи на `/api/gis-preview`, користувач **відразу** отримує запит до наявного `directory_entries` із `directory_id='settlements'`. Жодних нових таблиць, міграцій, імпорту чи синтетичних населених пунктів.
- Відключений демонстраційний шар можна ввімкнути окремо. Кнопки DEMO-інструментів та їхній експорт залишаються демонстраційними; вони не видають себе за експорт бази.
- У шарах доступні пошук за назвою, громадою та адміністративними одиницями, фільтр за типом, ручне оновлення й лічильник.
- Маркер відкриває назву, тип, громаду, район, область **із D1**, без військових координат, маршрутів, частот та секторів.
- Під час переміщення карти запити скасовуються і повторюються із затримкою 450 мс. Дані відфільтровано по координатах поточної області, завантажуються лише дозволені публічні поля.
- На низькому масштабі багато маркерів групуються в кластери, а не захаращують екран. Вибір кластера наближає карту.
- Ліміт 2 000 об’єктів на область і прапорець `truncated` відверто повідомляють про неповний результат; інтерфейс пропонує збільшити масштаб.
- Якщо D1 повертає 0 або помилку, на екрані буде явно вказано стан. Відсутність точок в області **не означає**, що весь довідник порожній.

### Верифікація після деплою

1. Після Cloudflare Access відкрити `/api/gis-preview`. Дочекатися напису `D1: … пунктів завантажено` або явної причини недоступності.
2. Переконатися, що підкладка OpenStreetMap завантажується, точки не є трьома умовними позначками.
3. Натиснути на цивільний населений пункт, застосувати пошук за назвою/типом, пересунути карту та наблизити кластер.
4. Якщо відображається 0, перевірити в D1 саме активні записи `directory_entries` з валідними `data_json.lat` та `data_json.lon` і їхню належність до поточної області. Не додавати вигаданих точок.
5. Запустити `cd api && npm test` і Worker `wrangler deploy --dry-run`. Ручний `Deploy ANALISE API` потрібен після PR; GitHub Pages сам по собі Worker не оновлює.

**Безпека:** інформація про військові БпЛА, ВП/СП, станції та географію їхніх дій у картографічний шар не переноситься.

## 18.10.2026 — стабілізація навігації й перевірка порожньої карти

Після розгортання PR #54 було підтверджено, що OSM підкладка працює, проте у видимій області немає цивільних маркерів, а навігація сіпається. Не можна підміняти 0 записів тестовими точками або робити висновок, що D1 порожня, лише за порожнім viewport.

- Навігаційне перетягування об'єднує події `pointermove` у `requestAnimationFrame`.
- Trackpad/wheel накопичує рух і обмежує швидкість кроків масштабу; `ResizeObserver` не запускає перемальовування, якщо розміри карти незмінні.
- Для цивільного шару порівнюються попередні та завершені межі огляду. Повторний `gis:map-changed` без географічної зміни не перезапускає D1-запит.
- Коли запит до цивільного довідника повернув порожню першу сторінку, API **окремим SELECT** запитує тільки кількість активних населених пунктів і кількість тих, що мають координати. Не читаються географія окремих записів та військові таблиці.
- Розрізняються три стани: порожній довідник, записи без придатних координат та відсутність об'єктів у поточній області. Невдалу перевірку джерела відображено як `unavailable`, не як 0.
- Виправлення не виконує `INSERT`, `UPDATE`, жодних міграцій, імпорту чи змін Cloudflare Access.

Після ручного Worker Deploy перевірити `/api/gis-preview`, перетягування мишкою, плавність масштабування, а також підсумок цивільного шару. Якщо вказано **записи без координат**, потрібен окремий аудит якості публічного довідника D1; цей PR не домислює координати й не створює точки.

## 18.10.2026 · Огляд областей і безпечний архів

До існуючої сторінки `/api/gis-preview` додані дві незалежні візуалізації, без нового проєкту, бази, міграцій або перезапису даних:

1. **Публічні населені пункти за областями** — маршрут `GET /api/gis/settlement-regions`, доступний тільки активному адміністратору через Cloudflare Access. Один read-only SQL `SELECT` групує записи `directory_entries` для `settlements` за полем `region` і повертає кількості всіх та геокодованих цивільних записів. Не повертає координат, конкретних об'єктів, маршрутів або військових даних. У лівій панелі показані правдиві регіональні стовпчики з назвою джерела. На масштабах нижче 7 у верхньому куті полотна з'являється короткий текстовий індикатор (НЕ географічні точки), а кнопка **«Показати точки на карті · Zoom 7»** наближає карту до реальних геокодованих населених пунктів.
2. **Історичні БпЛА** — читання вже наявного `GET /api/gis-uav-archive/data?year=YYYY` лише після натискання **«Читати архів»**. У лівій панелі показано безпечні квартальні агрегати, відфільтровані за класом. Використовуються тільки **завершені квартали з лагом 90 днів** та вже застосований сервером **поріг ≥20**. `null` показується як «—», а не як нуль; абсолютні суми прихованих клітин не виводяться. Джерело, період, доступність структурованого архіву та відмінність RAW від подій показані явно. Географії або точних військових подій/позицій немає.

Існуючі довідники `uav_models`, `vp_sp_objects`, `stations` продовжують незалежно відображатися у своїй панелі, з read-only підсумками. Робоче нанесення **цивільних** населених пунктів із D1 збережено; нові агрегати не малюють військових маркерів на географічній карті.

Верифікація: `api/tests/gis-overview.test.js`, чинні GIS regression tests, CI integrity та dry-run Cloudflare Worker, потім ручний `Deploy ANALISE API` на `main`. Після деплою відкрий карту, перевір регіональні числа при zoom 6, кнопку zoom 7, клікабельні цивільні маркери, вибір архівного року й категорії БпЛА. Наявність RAW без структурованого архіву — очікуване повідомлення, не вигадані агрегати.
