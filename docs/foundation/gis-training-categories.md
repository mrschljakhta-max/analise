# OSM MAP STUDIO · Підключені довідники D1

## Заміна DEMO-маркерів на достовірні джерела

Попередній набір із восьми умовних маркерів БпЛА/ВП/СП/станцій видалено з GIS-інтерфейсу. Ці фіксовані екранні значки **не читали D1** й створювали хибне враження роботи з геоданими.

У чинній карті `/api/gis-preview` тепер є панель **«ДОВІДНИКИ D1 · 3 ДЖЕРЕЛА»**, яка читає один admin-only endpoint `GET /api/gis/reference-summary`. Старі URL статичних GIS-ресурсів `/api/gis-training-layers.js` та `.css` збережено для сумісності, але їхній зміст повністю замінено.

| Джерело | Дані, що відображаються |
|---|---|
| `uav_models` | Реальні назви **активних моделей** БпЛА, класи «Крило / Мультироторний / FPV», достовірні підсумки за всіма моделями. Перші 100 назв, далі чесне повідомлення про обмеження та перехід у повний каталог |
| `vp_sp_objects` | Лише **агреговані** кількості ВП і СП, загальні та активні. Ні назв об'єктів, ні точних місцеположень |
| `stations + station_types` | Лише найменування **типів** станцій з D1 і кількості за типом, загальні та активні. Без позивних, номерів, підрозділів, характеристик чи координат |

Кожне джерело має незалежний стан: `available`, `schema_missing` або `query_failed`. Загальна відповідь `overall_status` розрізняє `available`, `partial` і `unavailable`. Неуспіх одного довідника не заважає іншим.

Інтерфейс підтримує ручне перечитування D1, категорійні фільтри, активні/усі для агрегованих груп, лічильники, картки та посилання на початкові адміністративні довідники. Жодних резервних DEMO-даних не використовується.

## Безпека

- Запити виконує **тільки адміністратор**, авторизований через Cloudflare Access. GET-only та `cache-control: no-store`.
- **Тільки SELECT** з `uav_models`, `vp_sp_objects`, `stations` і `station_types`.
- Не зчитуються записи `operational_report_events`, позивні станцій, підрозділи, координати, маршрути, частоти, параметри подавлення, дані ВП/СП про розташування чи службові поля.
- Джерела БпЛА/ВП/СП/станцій є **довідниками без геоприв'язки**. На географічній підкладці OSM залишаються лише відкриті цивільні населені пункти D1; їхній код/запити не змінюються.
- Підключення не робить імпорту, не вимагає міграцій та не змінює RAW або чинну D1.

## Приймальна перевірка

1. Після мерджу і **ручного Deploy ANALISE API** з `main` відкрити `/api/gis-preview`, оновити через Ctrl+Shift+R.
2. В лівій панелі побачити «ДОВІДНИКИ D1 · 3 ДЖЕРЕЛА», натиснути «Читати D1».
3. Побачити достовірну кількість записів і назви моделей із D1 або **конкретні повідомлення про помилки**, а не фіксовані числа 3/2/3.
4. Перевірити фільтр категорії, клацнути запис БпЛА, відкрити інспектор, звірити назву з оригінальним каталогом.
5. Перевірити, що ВП/СП і станції відображають лише безпечні агрегати, а віконце DEMO з восьми маркерів на карті відсутнє.
6. Увімкнути/вимкнути населені пункти, пересунути/масштабувати OSM. Робочий цивільний геошар має працювати як і раніше.
7. Перевірити `api/tests/gis-reference-summary.test.js`, `api/tests/gis-training-layers.test.js` та GitHub Actions. CI й GitHub Pages не замінюють ручний Worker Deploy.

## Єдине керування довідниковими шарами · 19.10.2026

Налаштування **ввімкнення й вимкнення невійськових за деталізацією, негеографічних довідникових панелей** зібрано у **`api/src/gis-reference-visibility.js`**. Це єдине місце для режимів відображення трьох джерел:

```js
export const GIS_REFERENCE_VISIBILITY = Object.freeze({
  uav:     Object.freeze({enabled:true,mode:"reference_only"}),
  vp:      Object.freeze({enabled:true,mode:"reference_only"}),
  station: Object.freeze({enabled:true,mode:"reference_only"})
});
```

Щоб приховати певну довідникову панель і припинити читання її підсумків у GIS API, можна встановити `enabled:false` для відповідного ключа. Для повернення — `enabled:true`. Один конфіг використовують серверний `/api/gis/reference-summary` та браузерний `/api/gis-training-layers.js`. Сторінка спочатку завантажує `/api/gis-reference-visibility.js` з тим же конфігом. Вимкнені джерела отримують стан `disabled` і не запитуються D1; кількість видимих довідників автоматично підраховується.

**Межа функціоналу:** це **тільки довідникові та агреговані панелі**. Ключ `mode:"reference_only"` не надає координат або права на геопозицію; зміна його на інший режим веде до приховування, а не до дозволу географії. Серверний SQL ніколи не повертає військові координати, позиції, сектори, маршрути чи журнали подій. Жодного перемикача в конфігу для їх відкриття немає. Географічне нанесення публічних цивільних населених пунктів регулюється окремо в GIS Civil API.

Перевірка: `api/tests/gis-reference-visibility.test.js` + наявні `gis-reference-summary.test.js`, `gis-training-layers.test.js`, Worker dry-run. Дані, схеми D1 та RAW не змінюються.
