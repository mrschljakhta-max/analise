# Універсальні довідники — етап реалізації

## Статус
Розробка ведеться в окремій гілці, без міграцій у production.
- D1 migration 0002: directory_types, directory_entries, directory_entry_audit.
- Авторизовані API: GET /api/directories, GET /api/directories/:id, GET/POST /api/directories/:id/entries, PATCH/DELETE /api/directories/:id/entries/:entryId.
- POST /api/directories/:id/preview та /batch: JSON `{"rows":[{"name":"Тестове","type":"село","community":"Тестова","district":"Тестовий","region":"Тестова область"}]}`; не більше 100 рядків за запит. Доступ тільки admin.
- Довідник settlements: 8 погоджених полів.

## Блокери перед прийманням
1. Валідація координат на сервері та узгодженість MGRS ↔ Lat/Lon; зараз схема перевіряє тільки наявність полів і базові типи.
2. Повноцінний XLSX-парсер на захищеному сайті, багатoаркушеві файли, розбиття на пакети.
3. Стійка ідентифікація рядків, дедуплікація, повторний імпорт без повторного створення.
4. Атомарний аудит редагувань і тестування конфліктів одночасних змін.
5. UI для preview/confirm, лічильники, помилки, контроль доступу та інтеграційні тести.
6. Застосувати міграцію на ізольованій тестовій D1, перевірити перезавантаження та читання.
7. Окремий аудит безпеки перед будь-якими реальними даними.

Не використовувати поточні endpoints для службових або оперативних даних.
