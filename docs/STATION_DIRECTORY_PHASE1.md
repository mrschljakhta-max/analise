# ANALISE — довідник станцій (етап 1)

Міграція: `api/migrations/0006_station_directories.sql`.

## Що реалізовано
- Окремі таблиці моделей, паспортних характеристик антен, екземплярів станцій, перемикачів антен та історії розміщень.
- Стабільні коди імпорту незалежні від внутрішніх ID.
- Власник станції — посилання на `org_units`.
- Не більше одного відкритого запису історії розміщення на станцію.
- Дальність зберігається в кілометрах як дробове число; частоти — МГц, кути — градуси.
- Дані станцій, координати та приклади реальних розміщень НЕ додаються автоматично.

## Застосування
З каталогу `api` після перевірки конфігурації D1:
```bash
npx wrangler d1 migrations apply <DATABASE_NAME> --local
npx wrangler d1 migrations apply <DATABASE_NAME> --remote
```
Назву бази необхідно взяти з `wrangler.toml`. Спершу протестувати на локальній/тестовій базі та створити резервну копію робочої.

## Потрібно до імпорту
1. Зіставити числові `station_type_id` з аркуша DICT_STATION_TYPE_BANDS зі стабільними ключами DICT_STATION_TYPES; не покладатися на порядок рядків.
2. Перевірити, чи існують кілька частотних записів на одну антену. Поточна схема має один запис характеристик на кожен вид антени в межах моделі; якщо потрібно кілька діапазонів, додати окрему таблицю діапазонів перед імпортом.
3. Реалізувати серверну валідацію: MGRS → WGS84, звірку типів, атомарне завершення історії та перевірку статусів.
4. Додати API, UI та перевірені тести. Цей коміт — лише структура БД.

## Безпека
Довідник — обліковий. У цьому етапі немає картографічної візуалізації, розрахунку покриття чи керування обладнанням.
